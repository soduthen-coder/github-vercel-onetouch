## 무엇이 달라졌나

두 저장소가 거의 같은 일을 하고 있었습니다. 합치면서 흐름을 하나로 줄였습니다.

**클로드에게 만들어 달라고 한 뒤, 올린다.**

빈 사이트를 처음부터 만들어 주던 기능(`new-site.sh`)은 덜어냈습니다.
클로드에게 "이런 페이지 만들어 줘" 라고 하면 될 일이라, 빈 템플릿을 따로
만들어 줄 이유가 없었습니다.

## 왜 저쪽이 확정판인가

이 저장소의 스크립트는 저쪽이 이미 고쳐 가진 것의 구버전입니다.
확인된 문제만 적으면 이렇습니다.

| 어디 | 무엇 |
|---|---|
| `lib/common.sh` | 로그인이 풀렸을 때 **없는 `setup.sh` 를 실행하라고** 안내합니다. 막다른 길입니다 |
| `publish.sh` | 이름 변환 결과를 버리고 **변환 안 된 원래 이름**으로 저장소를 만듭니다 |
| `publish.sh` | 저장소 주소를 폴더 이름으로 **추측해서** 보고합니다 |
| `remove-site.sh` | 삭제 실패 안내가 파이프 뒤에 있어 **절대 실행되지 않습니다**. 실패해도 조용히 넘어갑니다 |

저쪽에는 이것들이 없고, 추가로 버셀 CLI 가 `deploy --name` 을 걷어내는 데
대한 대응까지 들어가 있습니다.
