# 버셀 원터치

만든 웹페이지를 **인터넷 주소로 열리게 하는** 과정을 명령 하나로 끝냅니다.

```bash
bash start.sh
```

이 하나가 처음부터 끝까지 다 합니다.

```
필요한 프로그램 확인 → 도구 설치 → 로그인 → 계정 정보 저장
  → 사이트 만들기 → 깃허브 업로드 → 버셀 배포 → 진짜 열리는지 확인
```

끝나면 `https://my-first-site.vercel.app` 같은 주소를 돌려줍니다.

---

## 누가 써도 같은 명령입니다

**상황을 따질 필요가 없습니다.** 이미 되어 있는 것은 알아서 건너뜁니다.

| 지금 상태 | 해야 할 일 | 걸리는 시간 |
|---|---|---|
| 아무것도 없음 (계정도 없음) | `bash start.sh` | 5~10분 (가입 포함) |
| 깃허브·버셀 계정만 있음 | `bash start.sh` | 2~3분 |
| 계정 + 도구까지 있음 | `bash start.sh` | 약 20초 |
| 커넥터·플러그인까지 연동함 | `bash start.sh` | 약 20초 |

커넥터나 플러그인이 연동되어 있어도 **충돌하지 않습니다.** 이 도구는 커넥터를
쓰지 않고 명령줄 프로그램만 쓰기 때문에, 있든 없든 똑같이 동작합니다.

실행하면 맨 위에 지금 상황을 알려줍니다.

```
  상황: 준비 완료 — 바로 사이트를 만듭니다 (약 20초)
  이미 되어 있는 것은 자동으로 건너뜁니다.
```

## 직접 하신다면

```bash
git clone https://github.com/<아이디>/vercel-one-touch.git
cd vercel-one-touch
bash start.sh
```

**윈도우는 Git Bash**, 맥·리눅스는 기본 터미널에서 실행하세요.
(윈도우 PowerShell 이나 명령 프롬프트에서는 동작하지 않습니다.)

## 계정이 아직 없다면

`start.sh` 가 필요한 시점에 가입 주소를 알려주지만, 미리 만들어두면 더 매끄럽습니다.

### 깃허브 — 파일을 보관하는 곳 (무료)

1. **https://github.com/signup**
2. 이메일 → 비밀번호 → 사용자 이름 순서로 입력
   - 사용자 이름은 **영문·숫자·하이픈만** 됩니다. 한글은 안 됩니다
   - 나중에 주소에 쓰입니다: `github.com/내아이디/프로젝트이름`
3. 메일로 온 **8자리 코드**를 입력하면 완료 (안 보이면 스팸함 확인)

### 버셀 — 웹사이트로 띄워주는 곳 (무료)

1. **https://vercel.com/signup**
2. **`Continue with GitHub`** 를 누르세요
   - 방금 만든 깃허브 계정으로 바로 가입됩니다
   - 비밀번호를 새로 만들 필요가 없습니다
3. 깃허브가 권한을 묻으면 `Authorize Vercel`
4. 용도는 **Hobby(개인용, 무료)**

> 2단계 인증(Authenticator App)은 **설정하지 않아도 됩니다.** 가입에도 배포에도
> 필요하지 않습니다. 나중에 계정 보안을 더 챙기고 싶을 때 켜는 선택 기능입니다.

## 프로그램 두 개가 필요합니다

| | 받는 곳 | 무엇인가 |
|---|---|---|
| **git** | [git-scm.com/downloads](https://git-scm.com/downloads) | 변경 내역을 기록하고 깃허브에 올리는 프로그램 |
| **Node.js** | [nodejs.org](https://nodejs.org) | 버셀 도구 설치에 필요 (`npm` 이 함께 깔림) |

둘 다 **기본 설정 그대로 `다음`만** 누르면 됩니다.
`start.sh` 가 자동으로 설치하지는 않고, 없으면 주소를 알려주며 멈춥니다.
설치 후 **터미널을 껐다 켜세요.**

# 그 뒤로 쓰는 법

```bash
bash new-site.sh 이름 --title "제목"     # 사이트 더 만들기
bash publish.sh --dir 폴더 "메모"         # 고친 내용 올리기
bash protect.sh 이름 on                  # 나만 보기
bash protect.sh 이름 off                 # 다시 공개
bash protect.sh 이름                     # 지금 상태 확인
bash remove-site.sh 이름                 # 통째로 내리기
```

# 꼭 알아둘 것

## 이름은 영문, 제목은 한글

**한글 이름을 쓰면 깨집니다.** 실제로 겪은 문제입니다.

- 깃허브가 한글을 전부 버리고 `-` 한 글자짜리 저장소를 만듭니다
- 버셀은 `Detected linked project does not have "id"` 오류를 냅니다

그래서 이 도구는 영소문자·숫자·하이픈만 받고, 아니면 **시작 전에 막습니다.**

```bash
bash new-site.sh my-portfolio --title "나의 포트폴리오"
```

## 저장소 공개 ≠ 사이트 공개

둘은 따로 놉니다. **여기서 많이 헷갈립니다.**

| | 기본값 | 바꾸는 법 |
|---|---|---|
| 깃허브 저장소 (코드) | **비공개** | `--public` 또는 `protect.sh ... --repo` |
| 버셀 사이트 (웹페이지) | **공개** | `protect.sh <이름> on` |

**저장소를 비공개로 뒀다고 사이트까지 가려지는 것이 아닙니다.** 배포된 주소는
아는 사람이면 누구나 열 수 있습니다. 민감한 내용이 있다면 `protect.sh <이름> on`
을 꼭 실행하세요.

반대로 **과제 제출처럼 남이 링크를 열어야 하면 잠그면 안 됩니다.**

## 잠겼는지 확인하는 법

버셀은 **잠겨 있어도 HTTP 200 을 돌려줍니다.** 응답 코드만 보면 속습니다.
페이지 제목으로 판별하세요.

- `Login – Vercel` → 잠김
- 그 외 → 공개

`protect.sh <이름>` 이 이 확인을 대신 해줍니다.

## 올리면 안 되는 것

저장소를 공개로 두면 올린 파일이 **전부** 보입니다. 한 번 올라간 것은 나중에
지워도 **커밋 기록에 남습니다.**

`.gitignore` 에 아래가 기본으로 들어갑니다.

```
.env  .env.*  *.pem  *.key   ← 열쇠·비밀번호 파일
.vercel/                     ← 버셀이 만드는 토큰 폴더
```

개인정보가 든 데이터 파일은 직접 추가하세요.

# 파일 구성

```
start.sh          ★ 이것만 실행하면 됩니다 (준비 + 첫 배포)
new-site.sh       사이트 더 만들기
publish.sh        수정 반영
protect.sh        공개/비공개 전환
remove-site.sh    통째로 삭제
lib/common.sh     공통 함수 (직접 실행하지 않음)
config.sh         start.sh 가 만드는 내 계정 정보 (깃허브에 올라가지 않음)
CLAUDE.md         Claude Code 가 자동으로 읽는 지침
```

스크립트마다 맨 위에 무엇을 하는지, 각 줄이 왜 있는지 주석으로 적어 두었습니다.

# 문제가 생기면

| 증상 | 해결 |
|---|---|
| `git 을 찾을 수 없습니다` | git 설치 후 **터미널 재시작** |
| `npm 이 없습니다` | [nodejs.org](https://nodejs.org) 에서 Node.js 설치 |
| `gh 를 찾을 수 없습니다` | 터미널을 껐다 켜고 `bash start.sh` 다시 실행 |
| 깃허브 로그인이 안 됨 | 계정을 먼저 만드세요 (위 "계정이 아직 없다면") |
| 버셀이 인증 화면을 보여줌 | 2단계 인증은 필수가 아닙니다. 건너뛰어도 배포됩니다 |
| 저장소 이름이 `-` 로 생김 | 한글 이름을 쓴 것입니다. 영문으로 다시 만드세요 |
| `이미 있는 폴더입니다` | 다른 이름을 쓰거나 기존 폴더를 옮기세요 |
| 잠갔는데 열림 | `protect.sh <이름>` 으로 실제 상태를 확인하세요 |
| 저장소 삭제가 안 됨 | 삭제 권한이 없는 것입니다. `bash start.sh` 재실행 |

## 버셀 깃 연동은 왜 안 쓰나요

버셀 대시보드에서 저장소를 연결하면 `push` 만으로 자동 배포됩니다. 하지만
그러려면 **버셀 깃허브 앱에 저장소 접근 권한을 사람이 직접 켜줘야** 합니다.
새 저장소를 만들 때마다 그 벽에 부딪힙니다.

그래서 이 도구는 연동 대신 **스크립트가 직접 배포**합니다. 결과는 같고 사람 손이
들지 않습니다. 연동을 쓰고 싶으면 `github.com/settings/installations` 에서
Vercel 을 `All repositories` 로 바꾸면 됩니다. 필수는 아닙니다.
